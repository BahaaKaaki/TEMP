# Baseline / as-is diagnostic

## When to use this skill
Use when the ask is for an as-is assessment, current-state diagnostic, baseline, or fact base before strategy, operating model, or transformation design. It is the right skill when the team must establish the starting point and the case for change. Do not use for a target-state design or a benchmark-only deliverable.

## Executive summary
**One page only.**  
It should track the diagnostic and usually contain 3–5 components such as the current-state picture, main pain points, root causes, material gaps, and implications for what comes next.

## Typical output
Typical length: 6–12 pages in a standard version. This is the default structure for a broad ask; narrower requests may focus on one function or one diagnostic lens only.

### 0) Executive summary — 1 pages
**What it is:** One-page tracker for the baseline  
**What it includes:** current-state picture, major issues, root causes, implications, priority areas  
**Typical formats:** message page; diagnostic summary

### 1) Objective, scope, and assessment lens — 1 pages
**What it is:** What the diagnostic covers and how it is structured  
**What it includes:** scope boundaries, assessment dimensions, methodology lens  
**Typical formats:** scope page; assessment framework

### 2) Current-state fact base — 1–3 pages
**What it is:** The evidence on how the entity works today  
**What it includes:** performance snapshot, structure, service or product baseline, process and governance overview  
**Typical formats:** scorecard; current-state snapshot; process map

### 3) Stakeholder voice and pain points — 1–2 pages
**What it is:** What users and leaders say is not working  
**What it includes:** interview themes, pain points, recurring issues, aspiration signals  
**Typical formats:** pain-point matrix; quote synthesis; stakeholder map

### 4) Gap and root-cause synthesis — 1–3 pages
**What it is:** The issues that matter most and why they exist  
**What it includes:** root causes, issue clusters, dependencies, value leakage or friction  
**Typical formats:** issue tree; heatmap; root-cause analysis

### 5) Implications and priority areas — 1–2 pages
**What it is:** What the baseline means for the next step  
**What it includes:** priority gaps, design implications, key hypotheses, initial opportunities  
**Typical formats:** priority matrix; implication bridge; action themes

## How to build
- define the scope and the assessment lenses up front
- build the fact base from current performance, processes, governance, organization, and stakeholder input
- separate facts from interpretation before synthesizing the gaps
- cluster issues into a few decisive themes rather than listing every pain point
- show why the current state matters for the next design step
- make the output diagnostic and decision-useful, not just descriptive
- end with implications, priority gaps, and hypotheses for change

## Success criteria
The baseline is evidence-based, the pain points are prioritized, the synthesis is clear, and the client can see both the current-state picture and why it must change.

## Common failure modes
Inventory dump; excessive description with no synthesis; no prioritization; unsupported pain points; stakeholder quotes with no structure; no bridge from current state to next steps.
