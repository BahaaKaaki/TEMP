# Board-ready way-forward / transaction option recommendation

## When to use this skill
Use this when leadership must choose among a small number of high-stakes pathways—extend, acquire, transfer, build, partner, exit, or incorporate—and wants a short, board-grade recommendation grounded in economics, feasibility, and risk. Typical trigger phrases include “way forward,” “option assessment,” “extend vs buy vs build,” “transfer clause,” “board recommendation,” and “preferred pathway.” Do **not** use it for a broad strategy refresh or a full due-diligence report; this is a decision memo in deck form.

## Deliverable shape
1. **Recommendation and decision ask**  
   Purpose: make the board decision explicit from the first slide.  
   Typical length: 1 slide.  
   Complete when: the recommended path, required decision, and timing are clear.  
   Common failure modes: neutral summary, no recommendation, no deadline.

2. **Current-state baseline**  
   Purpose: establish the facts of the current arrangement or asset.  
   Typical length: 1–2 slides.  
   Complete when: contractual structure, performance, economics, and relevant obligations are visible.  
   Common failure modes: weak baseline, no clarity on what the current model actually is.

3. **Option set and evaluation criteria**  
   Purpose: define the choice architecture.  
   Typical length: 1 slide.  
   Complete when: options are MECE and criteria cover economics, risk, feasibility, timing, and strategic fit.  
   Common failure modes: overlapping options, hidden criteria, incomplete option set.

4. **Deep dive on each option**  
   Purpose: show what each path really entails.  
   Typical length: 2–4 slides.  
   Complete when: each option’s investment need, operating implications, legal burden, execution difficulty, and value logic are visible.  
   Common failure modes: superficial pros/cons, no transition burden, no hidden cost view.

5. **Comparative economics and value/risk trade-off**  
   Purpose: make trade-offs visible on one page.  
   Typical length: 1–2 slides.  
   Complete when: returns, cash need, downside risk, and feasibility are comparable across options.  
   Common failure modes: no comparable basis, over-precision on weak data, no risk weighting.

6. **Recommended option and rationale**  
   Purpose: explain why one path is better than the others.  
   Typical length: 1 slide.  
   Complete when: the recommendation is linked explicitly to the criteria and the rejected options are addressed.  
   Common failure modes: recommendation detached from comparison, weak rebuttal to obvious alternatives.

7. **Transition roadmap and board implications**  
   Purpose: show what happens after approval.  
   Typical length: 1–2 slides.  
   Complete when: milestones, approvals, legal steps, operating handover, and key risks are sequenced.  
   Common failure modes: recommendation without a path to execute, no board follow-on actions.

8. **Appendix and proof points**  
   Purpose: hold contract, DD, performance, and valuation support behind the recommendation.  
   Typical length: backup only.  
   Complete when: the evidence for baseline, assumptions, and option sizing is available.  
   Common failure modes: no backup for challenge questions.

## Visual framework library
- **Current-state — contract / operating model summary box**: use to make the baseline legible fast.
- **Option comparison — board scorecard**: options on rows, criteria on columns, with concise commentary instead of raw scoring where data are imperfect.
- **Economics — capex / return / timing comparison table**: use where options differ in speed and investment burden.
- **Risk — feasibility / risk heat map**: useful when economics alone do not decide the answer.
- **Decision tree — if/then page**: useful when the recommendation depends on one gating condition.
- **Roadmap — approval to transition timeline**: especially important for BOT expiry, transfer, or incorporation cases.

## House conventions
- **Action-title format**: titles should read like board language, e.g., “Extension preserves continuity but leaves material upside on the table; transfer is preferable if readiness actions begin immediately.”
- **Executive summary structure**: recommendation, why, and what the board must do next.
- **How findings are articulated**: baseline fact → option implication → comparative conclusion.
- **Tone**: sharp, direct, and candid about what is not yet proven.
- **Vocabulary**: “way forward,” “preferred path,” “gating condition,” “transfer burden,” “strategic fit,” “execution readiness,” “board approval.”
- **Decision discipline**: if data are imperfect, say so and frame ranges and conditions explicitly.

## Inputs the skill needs
- **Current-state contract / asset / performance view** (**Required**)
- **Option longlist / management hypotheses** (**Required**)
- **Financial and legal inputs** (**Required**)
- **Past DD / assessments** (**Optional but high value**)
- **Board decision timing** (**Required**)
- **Readiness constraints** (**Optional but high value**)

## Methodology anchors
- Keep the option set clean and mutually exclusive.
- Compare options on the same basis; boards dislike apples-to-oranges logic.
- Surface hidden transition burden—teams often underestimate transfer, insourcing, or incorporation complexity.
- Show the downside case, not only the central recommendation.
- Make the recommendation conditional if the gating evidence is not yet strong enough to be absolute.

## Done-state checklist
- The board can see the recommendation on page 1.
- The options are clearly defined and fairly compared.
- Economics, risk, and timing are shown together.
- Transition burden is visible.
- Rejected options are explicitly addressed.
- The recommendation can be defended under challenge.
- Immediate post-approval actions are clear.

## Composition notes
This skill often composes with **Strategic business case and feasibility study** and **Final client readout / board decision deck**. Use the business-case skill when the board is choosing whether to create a concept; use this skill when the board is choosing among a small number of pathways.

## Metadata
- **Primary sectors:** cross-sector  
- **Typical engagement duration:** 2–6 weeks  
- **Typical team size:** 2–4 consultants plus senior oversight  
- **Primary consumer seniority:** partner / board sponsor  
- **Decay risk:** low  
- **Suggested owner discipline:** strategy and deals
