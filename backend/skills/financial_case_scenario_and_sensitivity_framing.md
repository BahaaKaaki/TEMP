# Financial case / scenario and sensitivity framing

## When to use this skill
Use when the ask centers on forecasting, return profile, affordability, funding need, or robustness under different assumptions. Typical asks include financial sustainability, investment returns, affordability tests, scenario planning, and sensitivity-based decision support. Do not use for a full strategy or business case if the numbers are only one component of a broader storyline.

## Executive summary
**One page only.**  
It should track the full deck and usually contain 3–5 components such as the base case, key scenarios, decisive sensitivities, return or funding view, and implication.

## Typical output
Typical length: 8–12 pages in a standard version. This is the default structure for a broad ask; narrower requests may cover only one section or page, while deeper asks may extend the deck.

### 0) Executive summary — 1 page
**What it is:** One-page storyline tracker for the financial case  
**What it includes:** base case, scenario range, key sensitivities, result, implication  
**Typical formats:** message page; financial summary; recommendation page

### 1) Value-driver logic — 1–2 pages
**What it is:** What drives the economics and why  
**What it includes:** key drivers, metric definitions, economic logic, model architecture at a high level  
**Typical formats:** value driver tree; bridge; assumptions map

### 2) Base case assumptions — 1–2 pages
**What it is:** The reference case used for decision-making  
**What it includes:** starting point, assumption set, key operational and financial assumptions  
**Typical formats:** assumptions table; baseline snapshot; input summary

### 3) Base case outputs — 1–2 pages
**What it is:** The economics of the reference case  
**What it includes:** revenue or benefit view, cost view, capex, cash flow, returns, affordability or funding need  
**Typical formats:** P&L summary; waterfall; cash flow chart

### 4) Scenario framing — 1–2 pages
**What it is:** A small set of distinct future states  
**What it includes:** scenario logic, what changes in each case, why the scenarios matter  
**Typical formats:** scenario matrix; case cards; planning grid

### 5) Sensitivity analysis — 1–2 pages
**What it is:** What variables matter most  
**What it includes:** key swing factors, upside/downside range, break-even thresholds  
**Typical formats:** tornado chart; spider chart; break-even curve

### 6) Funding, liquidity, or return view — 1–2 pages
**What it is:** How the case performs financially under capital constraints  
**What it includes:** funding profile, payback, IRR, NPV, liquidity, covenant or affordability implications  
**Typical formats:** funding bridge; return table; dashboard

### 7) Decision implication — 1–2 pages
**What it is:** What management should conclude from the numbers  
**What it includes:** recommended stance, guardrails, trigger points, follow-up actions  
**Typical formats:** decision page; guardrail table; action plan

## How to build
- define the financial question and the core decision metric
- make the value-driver logic explicit before showing outputs
- build a transparent base case
- select a small number of meaningfully different scenarios
- test the few variables that truly swing the result
- show returns, funding, and downside together
- convert the analysis into a recommendation or management implication

## Success criteria
The base case is explicit, scenarios are meaningfully different, sensitivities focus on real swing factors, and the output shows what management should do with the result.

## Common failure modes
Too many scenarios; buried assumptions; mixing one-offs and run-rate; sensitivity on trivial variables; no link from analysis to decision; numbers without narrative.
