# Kick-off, workplan, and data request pack

## When to use this skill
Use this at the start of a strategy, operating model, feasibility, or reform engagement when alignment on scope, governance, workplan, stakeholders, and data is still fragile. Typical trigger phrases include “kick-off deck,” “detailed workplan,” “data request,” “governance setup,” and “mobilization pack.” Do **not** use it once the engagement is underway; switch to the weekly SteerCo / PMO status deck after mobilization.

## Deliverable shape
1. **Engagement objective and success definition**  
   Purpose: restate what the engagement is trying to achieve and what “good” looks like.  
   Typical length: 1 slide.  
   Complete when: objectives, core deliverables, and approval endpoint are clear.  
   Common failure modes: copying proposal language without sharpening the actual problem.

2. **Scope boundary and assumptions**  
   Purpose: lock what is in and out before work starts.  
   Typical length: 1–2 slides.  
   Complete when: in-scope topics, out-of-scope areas, working assumptions, and open questions are explicit.  
   Common failure modes: scope drift from day one, hidden assumptions.

3. **Workplan and phasing**  
   Purpose: show how the work will be done.  
   Typical length: 1–2 slides.  
   Complete when: phases, workstreams, milestones, and expected outputs per phase are visible.  
   Common failure modes: only a calendar view, no linkage to outputs, no milestone logic.

4. **Governance and meeting cadence**  
   Purpose: define who decides, who reviews, and how often.  
   Typical length: 1 slide.  
   Complete when: steering committee, working sessions, weekly status, playback sessions, and escalation path are clear.  
   Common failure modes: no cadence, too many forums, no decision owner.

5. **Stakeholder map and engagement plan**  
   Purpose: make stakeholder access and workshop rhythm explicit.  
   Typical length: 1–2 slides.  
   Complete when: key stakeholders, interview/workshop purpose, and timing are stated.  
   Common failure modes: vague stakeholder list, no ownership for arranging access.

6. **Data request and document inventory**  
   Purpose: specify what is needed from the client.  
   Typical length: 1–3 slides.  
   Complete when: required inputs are grouped by workstream, priority, owner, and due date.  
   Common failure modes: generic data dump, no sequencing, no distinction between must-have and nice-to-have.

7. **Ways of working and responsibilities**  
   Purpose: set expectations for the joint team.  
   Typical length: 1 slide.  
   Complete when: consultant role, client role, review turnaround expectations, and draft/final process are explicit.  
   Common failure modes: no agreement on review cycle, unclear draft ownership.

8. **Immediate next steps and first 2–4 week plan**  
   Purpose: create momentum.  
   Typical length: 1 slide.  
   Complete when: the next deliverables, interviews, and milestones are locked.  
   Common failure modes: kick-off ends with no actions or dates.

## Visual framework library
- **Workplan — phase chevron with outputs under each phase**: use to reinforce that activities and deliverables follow the same spine.
- **Governance — simple forum ladder**: steering committee, project team, working groups, playback sessions. Use instead of a dense governance chart.
- **Stakeholder map — role-based matrix**: stakeholder, role in project, engagement method, target date.
- **Data request — prioritized tracker**: required input, why needed, owner, due date, workstream. Use this rather than an unstructured appendix.
- **First month plan — 30-day milestone calendar**: workshops, interviews, requests, first syntheses. Use when sponsor wants rapid momentum.

## House conventions
- **Action-title format**: even the kick-off deck should use titles that land implications, not labels.
- **Executive summary structure**: one page max—objective, workplan, governance, and asks.
- **How findings are articulated**: this pack is not analytical, but it should still explain why each ask matters.
- **Tone**: clear, practical, and no-surprises.
- **Vocabulary**: “mobilization,” “data request,” “playback,” “SteerCo,” “working session,” “acceptance criteria,” “RAID.”
- **Expectation setting**: be explicit on turnaround times, access, and approvals.

## Inputs the skill needs
- **Approved proposal or agreed scope** (**Required**)
- **Core client contacts and stakeholder list** (**Required**)
- **Initial hypotheses / workstreams** (**Required**)
- **Decision calendar** (**Optional but high value**)
- **Known data sources / repositories** (**Optional**)
- **Team structure** (**Required**)
- **Constraints on access / confidentiality** (**Optional**)

## Methodology anchors
- Lock scope and assumptions before launching interviews.
- Group data requests by workstream and priority; the client should know what is truly critical.
- Publish the cadence early; governance confusion creates rework later.
- Distinguish between steering/decision forums and working forums.
- End the pack with specific asks, names, and dates.

## Done-state checklist
- The sponsor can explain the workplan and governance after one read.
- In-scope and out-of-scope are explicit.
- Data requests are prioritized and owned.
- Stakeholder interviews and workshops are scheduled or schedule-ready.
- The draft / review / final process is clear.
- Immediate next steps are visible.
- There is an escalation path for data delays or stakeholder access issues.

## Composition notes
This skill usually composes first, then hands off to **Weekly SteerCo / PMO status deck** for the running cadence. It also composes naturally with any major substantive skill in this library.

## Metadata
- **Primary sectors:** cross-sector  
- **Typical engagement duration:** 1–2 weeks  
- **Typical team size:** 2–5 consultants  
- **Primary consumer seniority:** analyst / manager  
- **Decay risk:** low  
- **Suggested owner discipline:** project management and engagement setup
