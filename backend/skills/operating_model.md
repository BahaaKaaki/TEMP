# Operating model

## When to use this skill
Use for a new entity, mandate change, strategy refresh, transformation, post-merger integration, scale-up, service redesign, or when accountabilities and delivery logic are unclear. Do not use for a narrow org-chart exercise with no broader delivery-model question.

## Executive summary
**One page only.**  
It should track the full deck and usually contain 3–5 components such as mandate, core operating model choices, target-state implications, priority gaps, and implementation direction.

## Typical output
Typical length: 10–16 pages in a standard version. Use this as the default for a broad ask; narrower asks may focus on one section or page, while deeper asks may extend the deck.

### 0) Executive summary — 1 page
**What it is:** One-page storyline tracker for the operating model deck  
**What it includes:** answer, 3–5 messages, target-state implication, implementation direction  
**Typical formats:** message page; pillar summary; target-state snapshot

### 1) Mandate and design context — 1–2 pages
**What it is:** What the entity must enable and what the operating model needs to solve  
**What it includes:** mandate, boundaries, strategic context, design questions  
**Typical formats:** context page; issue tree; strategy house

### 2) Current-state diagnostic — 1–3 pages
**What it is:** How the model works today and where the main gaps sit  
**What it includes:** pain points across services, governance, organization, processes, capabilities, enablers  
**Typical formats:** heatmap; current-state snapshot; gap summary

### 3) Design principles and choices — 1–2 pages
**What it is:** Core principles and choices shaping the target model  
**What it includes:** centralization, sourcing, interfaces, control vs execution, channel choices, stakeholder model  
**Typical formats:** principles page; 2x2; choice matrix

### 4) Target operating model — 2–4 pages
**What it is:** The future-state model across the main layers  
**What it includes:** service model, governance, processes, organization, people, technology/data, key interfaces  
**Typical formats:** layered TOM; interaction model; service blueprint

### 5) Organization and governance implications — 1–2 pages
**What it is:** How the model changes accountabilities and leadership mechanisms  
**What it includes:** high-level structure, decision rights, forums, reporting lines, accountability shifts  
**Typical formats:** org chart; governance map; RACI

### 6) Transition roadmap — 1–2 pages
**What it is:** How the target model will be landed  
**What it includes:** sequencing, milestones, dependencies, quick wins, longer-term changes  
**Typical formats:** roadmap; phased plan; chevron with sub-steps

### 7) KPIs and management system — 1–2 pages
**What it is:** How the model will be tracked and managed  
**What it includes:** operating KPIs, governance cadence, performance review logic  
**Typical formats:** KPI scorecard; cadence view; governance chart

## How to build
- clarify mandate, scope, and the decision the model must enable
- diagnose current-state pain points across services, governance, processes, and capabilities
- define design principles and a small set of design choices
- design the target model across the key layers that matter
- synthesize the model into a clear target-state picture
- translate the model into roadmap, ownership, and governance

## Success criteria
Clear delivery logic; explicit design choices; no ambiguity on who does what; service, process, organization, and governance layers are aligned; roadmap is practical.

## Common failure modes
Too conceptual; no real design choices; org chart without delivery logic; weak link to services and processes; no transition path.
